Bases de datos relacionales

Una base de datos relacional es un tipo de base de datos que organiza los datos en tablas compuestas por filas y columnas. Cada tabla contiene datos sobre un tema específico, y las tablas pueden estar relacionadas entre sí mediante claves primarias y externas.

Las características principales de este modelo son:

  1. Estructura en tablas: Los datos se almacenan en tablas, donde cada fila representa un registro y cada columna un atributo del registro.
  2. Relaciones: Las tablas pueden estar relacionadas entre sí mediante claves, lo que permite realizar consultas complejas y obtener información combinada de varias tablas.
  3. SQL: Se utiliza el lenguaje SQL (Structured Query Language) para gestionar y consultar los datos.
  4. Propiedades ACID: Las bases de datos relacionales garantizan la Atomicidad, Coherencia, Aislamiento y Durabilidad de las transacciones.

Bases de datos NoSQL

Las bases de datos NoSQL (Not Only SQL) son un tipo de base de datos no relacional que permite almacenar y consultar datos de manera diferente a las bases de datos relacionales tradicionales. Aquí te dejo algunas características clave:

  1. Flexibilidad de Esquema: No requieren un esquema fijo, lo que permite almacenar datos no estructurados o semiestructurados, como documentos JSON.
  2. Escalabilidad Horizontal: Pueden escalarse fácilmente añadiendo más servidores en lugar de mejorar el hardware existente.
  3. Alta Disponibilidad y Fiabilidad: Al ser distribuidas, los datos se copian y almacenan en varios servidores, lo que garantiza que la base de datos siga funcionando incluso si algunos servidores fallan.
  4. Velocidad y Rendimiento: Son ideales para aplicaciones que requieren baja latencia y altas velocidades de consulta.

Existen varios tipos de bases de datos NoSQL, cada una optimizada para diferentes casos de uso:

  1. Bases de datos de documentos: Almacenan datos en colecciones, siendo los elementos de cada una de esas colecciones documentos que contienen pares clave/valor. Es como un sistema que nos permite almacenar elementos especificados por el lenguaje JSON. Cada documento puede tener una estructura diferente, como hemos señalado antes, lo que facilita la adaptación a cambios en el esquema de datos incluso entre documentos que pertenecen a una misma colección.
  2. Bases de datos tabulares: Son más conocidas en el sistema de bases de datos del modelo relacional, pero también las encontramos en el modelo NoSQL, aunque en menor medida. Este modelo permite el almacenamiento en tablas, aunque admiten mayor versatilidad, ya que permite variar el formateo de los registros en ellas.
  3. Bases de datos orientadas a grafo: Este modelo de bases de datos NoSQL está compuesto por documentos que se relacionan entre sí y que permiten representar relaciones complejas entre los datos. Son ideales para aplicaciones que requieren un alto nivel de conectividad como redes sociales, bases de conocimiento o inteligencia artificial.
  4. Bases de datos de clave-valor: Son las más sencillas de todas y almacenan datos en una organización de pares de clave y valor. Son las que permiten más altas velocidades en la lectura y escritura de datos y se usan principalmente en sistemas de almacenamiento en caché.
  5. Bases de datos multivalor: Permiten trabajar también con pares clave/valor, solo que permiten almacenar múltiples valores asociados a una clave. Esto puede hacerlas útiles para aplicaciones que gestionan datos complejos y variables.
  6. Bases de datos de tiempo real (Time-Series): Especializadas en trabajo con datos en tiempo real. Este modelo de sistemas gestores de bases de datos nos ofrece actualizaciones inmediatas de los datos que hemos consultado, propagando los valores en el caso que haya cambios.
  7. Bases de datos de almacén de objetos (Object Store): Son elementos más abstractos que los documentos, ya que pueden incluso servir para almacenar binarios o archivos multimedia. Son ideales para aplicaciones que gestionan imágenes o contenido multimedia.
  8. Bases de datos de Memoria (In-Memory): Almacenan datos en la memoria RAM del ordenador, en lugar de en discos. Esto supone una altísima velocidad, aunque también una mayor volatilidad de la información.
  9. Bases de datos distribuidas: Los datos pueden almacenarse en distintos sistemas alejados, incluso en distintas redes. Estos sistemas se conocen como nodos, que pueden albergar a una misma base de datos aportando mayor disponibilidad o replicabilidad. Son adecuadas para una escalabilidad horizontal y la distribución geográfica de los datos en lugares distintos de redes.

  1. Por un lado, encontramos MySQLi, que es una extensión de PHP diseñada para interactuar con bases de datos MySQL o MariaDB. Proporciona una interfaz más moderna y mejorada, además soporta tanto el enfoque procedural como el orientado a objetos, ofreciendo mayor flexibilidad a los desarrolladores. Para utilizar MySQLi orientado a objetos, se crea una instancia de la clase mysqli, pasando como parámetros el nombre del servidor, el nombre de usuario, la contraseña y el nombre de la base de datos.
  2. Por otro PALABRA PHP Data Objects (PDO) es una extensión de PHP diseñada para interactuar con bases de datos mediante una interfaz unificada. Esta extensión permite ejecutar operaciones como consultas y actualizaciones de datos utilizando una misma sintaxis, independientemente del tipo de base de datos. PDO soporta múltiples controladores de bases de datos, como MySQL, MariaDB, PostgreSQL, SQLite, SQL Server, Oracle Database, y más, facilitando la portabilidad del código. Para utilizar PDO, se crea una instancia de la clase PDO, pasando como parámetros el DSN (Data Source Name), el nombre de usuario y la contraseña.

Las ventajas de PDO en comparación con MySQLi son significativas y variadas, destacándose en diversos aspectos que mejoran tanto la funcionalidad como la usabilidad de la interacción con bases de datos:

  • Soporte para múltiples tipos de bases de datos: PDO no se limita solo a MySQL y MariaDB; permite trabajar con diversas bases de datos como PostgreSQL, SQLite, SQL Server, Oracle Database, entre otras.
  • Portabilidad del código: al usar una API unificada, el código se puede migrar fácilmente entre diferentes Sistemas Gestores de Bases de Datos (SGBD).
  • Manejo de excepciones: PDO ofrece un manejo robusto de excepciones, facilitando la gestión y depuración de errores.

Aunque en general se recomienda usar PDO sobre MySQLi, hay casos muy específicos en los que MySQLi es una mejor opción. Por ejemplo, cuando se requiere la funcionalidad más reciente y particular de MySQL o MariaDB.

MySQL

MySQL es una base de datos relacional que utiliza SQL para gestionar y manipular datos. Es conocida por su facilidad de uso, robustez y amplia adopción en aplicaciones web.

Ventajas:

  1. Facilidad de uso: MySQL es fácil de instalar y configurar, lo que la hace accesible para desarrolladores de todos los niveles.
  2. ACID Compliance: Garantiza transacciones seguras y consistentes, lo cual es crucial para aplicaciones que requieren integridad de datos.
  3. Amplio soporte y comunidad: Hay una gran cantidad de recursos, documentación y soporte comunitario disponibles.
  4. Compatibilidad: Funciona bien con muchas plataformas y lenguajes de programación.

Limitaciones:

  1. Escalabilidad vertical: Aunque puede escalar horizontalmente, MySQL se beneficia más de la escalabilidad vertical (añadir más recursos a un solo servidor), lo que puede ser un problema para aplicaciones con grandes volúmenes de datos.
  2. Rendimiento en grandes volúmenes de datos: Puede no ser tan eficiente como las bases de datos NoSQL en manejar grandes cantidades de datos distribuidos.

Apache Cassandra

Apache Cassandra es una base de datos NoSQL distribuida diseñada para manejar grandes cantidades de datos en múltiples servidores sin un punto único de fallo.

Ventajas:

  1. Escalabilidad horizontal: Puede escalar fácilmente añadiendo más nodos al clúster, lo que la hace ideal para aplicaciones con grandes volúmenes de datos.
  2. Alta disponibilidad: Diseñada para no tener un punto único de fallo, asegurando que los datos estén siempre disponibles.
  3. Rendimiento: Excelente para aplicaciones que requieren alta velocidad de escritura y lectura, como sistemas de mensajería y análisis de datos en tiempo real.

Limitaciones:

  1. Complejidad: La configuración y gestión de Cassandra pueden ser más complejas en comparación con MySQL.
  2. Consistencia eventual: A diferencia de MySQL, Cassandra no garantiza la consistencia inmediata de los datos, lo que puede ser un problema para ciertas aplicaciones que requieren datos siempre actualizados.

De cara a utilizar uno u otro, va a depender de las características que necesitemos de la base de datos, por ejemplo, si la aplicación web requiere transacciones seguras y consistentes, como en sistemas de pago o gestión de inventarios, MySQL podría ser la mejor opción debido a su cumplimiento ACID y facilidad de uso. Por el contrario, si la aplicación necesita manejar grandes volúmenes de datos distribuidos y requiere alta disponibilidad y escalabilidad, como en aplicaciones de redes sociales o análisis de datos en tiempo real, Apache Cassandra sería más adecuada.
